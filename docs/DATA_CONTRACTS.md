# Data contracts

The site consumes only `site/public/data/*.json`, validated against `data/contracts/<name>.schema.json` (JSON Schema 2020-12, generated by
`pipelines/contracts.py`, the single source of truth). TypeScript types are generated from these files. Conventions follow P01/P02:
`schema_version: "v1"`, a `tags` map (field group to honesty tag), compact JSON, sorted keys, no NaN (missing is `null`, never zero, never interpolated).
Tags: OBSERVED / DERIVED / PREDICTED / SIMULATED / SYNTHETIC (SIMULATED and SYNTHETIC unused), "/" combinations allowed.

## Conventions
- **Countries:** `iso3` list order is fixed by `countries.json` (217 entries, sorted by iso3). Every country-major array uses that order.
- **Years:** `years` is a list (1990 to the last WDI year); panel rows are country-major: `values[country_index][year_index]`.
- **Money basis (type-level PPP vs nominal):** every level indicator has `price_basis` in `current_usd | constant_usd_<yr> | ppp_constant_intl_<yr> | maddison_intl_2011`; non-money series have `null`.
  Level comparisons, rankings, regressions and cluster features must use one basis. The reference implementation is `analytics/units.py::assert_same_basis`, which raises `MixedBasisError`.
  Browser code must reproduce this guard (`indicators.json` is the lookup).
- **Latest year:** per indicator, the latest year whose country count is at least 90 percent of that indicator's peak yearly count in 2010 to 2022 (rule and N published in `coverage.json` and `indicators.json`).
- **Rankings:** only countries with a value that year; `n` published; ties broken by iso3; descending by value.
- **Growth figures:** `100*(ln y_end - ln y_start)/(end-start)`, percent per year (log growth rate), DERIVED.
- **Size budget:** each artifact under 400 KB gzip; measured sizes in `meta.json.artifact_bytes`.

## Raw / interim (not published)
`data/raw/**` (gitignored; `uv run python -m pipelines.ingestion.fetch` re-creates it), `data/interim/*.parquet` (cleaned long panel), `data/manifests/{raw_manifest,cleaning_ledger}.json`.
Interim long panel: `(iso3, year, indicator, value)`.

## Boundary table semantics
`boundaries.json.rows[]`: `iso3`, `entity`, `event`, `event_year`, `event_evidence` (`GENERAL_KNOWLEDGE`), `first_year_observed` (`DATA`, per `gdppc_const`),
`territory_break_year` (year inside the WDI series after which territory differs, or null), `treatment` (text), `sensitivity_only` (bool).
A country with `territory_break_year` inside (start, end] of a beta window is excluded from the primary sample of that window and included in the `sensitivity_all` record.
Countries with no data at the window start drop out of that window automatically (listed in the record's `dropped_no_start_data`).

## Seed-head data requests DR-1..DR-8 (P05-DATA-002; VISUAL_DESIGN 6.2)

| DR-1 | Done, with one declared deviation | `seedhead/<indicator>.json` per rankable indicator (17 files; `gdppc_ppp` has every year 1990 to latest, warm-started year to year; others have `rankings.snapshot_years` + latest where n >= 30) and `seedhead/gdppc_ppp_latest.json`. Schema `seedhead.schema.json`. Lattice: Vogel, golden angle 137.50776 degrees, slot area 1, one slot = 1,000,000 people. **Counts:** `max(1, floor(pop/1e6 + 0.5))` per country (half-up, per country, independent of sort order); population is the published `panel_income.population` value (rounded to 0 decimals) of the same year. A country under 0.5M people holds one slot drawn at `area_scale = pop / (count x 1e6)` (less than 1). `order` is descending by the indicator's published (rounded) value, ties by iso3, identical to `rankings`. `owner[i]` is the index into `order` of the country holding lattice slot i (base64 uint8; at most 217 countries). `no_data` lists countries with population but no indicator value that year (their people are not drawn). `median_person` is the country containing the median person among people-with-data ranked by the indicator. **Algorithm:** the reference `design/sketches/territories.py` (power assignment with weights, centroid relaxation, exact greedy repair), ported to `analytics/seedhead.py` (same cost and update rules; the squared distance is computed by the expanded square, iterations 600 cold start, 200 warm start). **Deviation:** the reference leaves 17 to 39 of 185 territories fragmented (checked on 2025), so a deterministic count-preserving contiguity repair (`polish`: stranded fragment handed to a neighbour, ripple of boundary grains back to the owner) is added after the greedy repair. Connectivity is the fraction of a territory's slots in its largest 6-nearest-neighbour component; per layout `connectivity.{min, mean, below_95}` is published, and the tests state the achieved result rather than assuming it. Warm start uses each country's previous centroid; a country absent the previous year gets its rank seed. **Connectivity achieved:** across all 20,367 territory-layouts, 5 (0.02 percent) are below 95 percent connected (worst 0.67, a 3-slot territory); the latest PPP layout has none. Size and byte-identical reruns are tested. **Size, measured:** `gdppc_ppp.json` (36 years) 121 KB gz, `gdppc_ppp_latest.json` 4.6 KB gz, each other indicator 15 to 19 KB gz (5 layouts), 17 snapshot files and the PPP file together about 400 KB gz. The critical path (latest file) and the PPP year scrubber (one file) are within budget, every file is lazy per indicator, and every file is far below the 400 KB per-artifact limit. ## P05-DATA-003: rank-order bound and DR-9
| ID | Status | Where and how |
|---|---|---|
| Rank-order bound | Done | The first published layouts drifted from rank order through the warm-start chain (rank vs centroid-radius Spearman 0.82 in 1990 to 0.63 in 2025; the USA sat at r 0.44, so the disc had no core). Fix in `analytics/seedhead.py`: (1) a **rank-radius anchor**: during the power iteration each site's radius is pulled 50 percent toward its rank radius `sqrt((cumulative slots before + count/2) / N)` every iteration, keeping its angle; (2) warm start keeps the previous year's **direction** but takes the **radius from the current rank**; (3) any layout whose rank-radius Spearman is below 0.85 is re-solved cold from rank-seeded sites. The exact repair, the contiguity repair and exact counts are unchanged. Every layout publishes `rank_order = {rank_radius_spearman, max_radius_deviation, solved_cold}` (Spearman between rank index and centroid radius; max over countries of |centroid radius - rank radius|, in lattice-radius units where the disc radius is 1). Tests assert Spearman >= 0.80 for every layout (the build enforces 0.85 through the cold fallback) and that the latest PPP layout's 10 richest countries have centroid radius <= 0.25. Layout acceptance is now: rank-radius Spearman >= 0.85 and at most one territory under 95 percent connected, else the next deterministic candidate (cold solves with other iteration counts) is tried and the best kept; a count-preserving `reseed` returns stranded territories (centroid radius more than 0.2 from rank radius) to their rank position. Result: PPP Spearman 0.91 (1990) to 0.99, min 0.89 over all PPP years and 0.87 over all 18 files; latest PPP layout Spearman 0.979 with the 10 richest within radius 0.25 (USA below 0.3). Connectivity: 9 of 20,367 territory-layouts under 95 percent (was 5). **Continuity cost:** mean centroid displacement between consecutive PPP years rose from 0.027 to 0.391 disc radii (15 of 36 PPP years are cold re-solves); territories no longer drift smoothly, they reflow with rank. |
